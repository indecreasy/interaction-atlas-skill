# 接入任意项目与需求库

第一次接手时，先问代码和需求分别在哪里。能从工作区、现有文档或用户给出的链接确认的，直接使用。地图只要求最终能描述“从哪里，做什么，发生了什么，以及依据在哪里”；产品可以继续使用自己的代码结构、字段、工作流和命名。

## 从项目找到真实行为

| 已有材料 | 从哪里入手 | 容易漏掉的情形 |
| --- | --- | --- |
| 网页路由与组件 | 路由注册、链接与按钮、弹层和表单提交回调 | 地址没变但用户已经进入编辑、确认或错误状态 |
| 原生或跨端 App | 导航容器、展示/关闭处理、标签切换、系统回调 | 同一页从通知、搜索和列表进入时返回目的地不同 |
| 声明式流程或状态机 | 状态、事件、守卫条件和副作用 | 相同动作在不同权限、角色、数据状态下结果不同 |
| 设计稿或需求原型，尚无代码 | 页面、热点与明确记录的产品决定 | 只有推测的转场应标待确认，整条流按方案展示 |

选择一条有入口和出口的流程抽样。记录动作证据的位置，例如一个提交内的文件路径与函数名，或一条验收条件。若只看到路由列表，把它当页面清单；补查实际调用点后再画箭头。

## 保留原需求库

- 仓库里的 Markdown、表格或 JSON，可直接引用相对路径和稳定条目编号。导出表格只有行号时，给地图记录分配稳定 ID，并保留原表的定位字段。
- GitHub Issues、Jira、Linear、Notion 或自建系统，可使用原系统的 ID、状态文字、标题与永久链接。多个来源的编号可能相同，可用“来源 + 原编号”作为内部键，界面仍显示用户熟悉的编号。
- 没有需求库时，先把可确认的动作画出来。用本地依据记录来源，缺失的归属标“待关联”，让没有依据和明确没有需求这两种情况可区分。已有需求而代码未实现时，可直接建立规划层。
- 用户给了导出文件就读取导出；有已授权连接才从系统读数据。需要让地图在离线时也可浏览，可在版本库保存获准共享的最小索引。来源不可访问时记录核对日期与缺口。
- 同一页面可以涉及多条需求。关联可以落到动作，例如“从通知进入详情”和“从列表进入详情”分别归属不同任务。状态显示沿用原系统；规划图层由该行为的实际实现证据决定，不能仅凭状态名猜测。

## 两个接入例子

一个库存 Web 应用用工单 `OPS-42` 描述“从缺货提醒打开补货单”。从提醒处理函数和提交回调提取 `alert → reorder → confirmation`，动作引用工单 URL，手机预览换成该产品的实际桌面表单。若同一表单也能从商品详情进入，取消时分别验证两个来源。

另一个桌面应用只有一份中文验收表。可以用“表名 + 条目键”标识“设置面板取消后保留旧值”，保留表内状态“已联调／待走查”。若代码显示取消已生效而表中仍待验收，分别记录两者，不把开发状态擅自改为完成。

在复杂项目中可以从团队已有的路由清单或需求导出生成地图模型。把转换放在项目自己的适配脚本中，分别处理读取、字段映射与证据关联；公共导航、关系图和走查播放器仍只消费地图数据。初次接入或小型项目，手工维护少数记录即可。

## 转换脚本要输出什么

复制模板后，`model.js` 在 `globalThis.ATLAS` 上暴露一个对象。以下是一个完整的最小模型；把它写入生成目录的 `model.js`，可直接从收件箱打开详情，再返回。工单链接为示例地址，接入时换成自己的来源。

```js
globalThis.ATLAS = {
  title: '运维工作台',
  start: 'inbox',
  initialState: {},
  requirements: [
    { id: 'OPS-42', title: '从告警进入详情', status: '联调中',
      source: 'https://example.org/issues/OPS-42' }
  ],
  pages: [
    { id: 'inbox', title: '收件箱', group: '处理', description: '当前告警。',
      requirements: ['OPS-42'] },
    { id: 'detail', title: '告警详情', group: '处理', description: '查看选中的告警。',
      requirements: ['OPS-42'] }
  ],
  actions: [
    { id: 'inspect', from: 'inbox', to: 'detail', label: '查看告警',
      kind: 'open', requirements: ['OPS-42'] },
    { id: 'return', from: 'detail', to: '$back', label: '返回',
      kind: 'back', requirements: ['OPS-42'] }
  ]
};
```

- 用 `initialState` 保存简单的演示值。`when` 按状态筛选动作，`effects` 可以设置值、复制值、翻转布尔值。借助页面的 `enter` 初始化编辑草稿，返回时才不会丢掉来源页的选择。
- 对尚未发版的节点或动作使用 `planned: true`。没有动作或页面指向的需求仍可保留在需求列表。用 `walks` 为复杂流程登记起点、动作 ID 序列和预期结果。具体写法见[离线模型](../assets/starter/model.js)。
- 预览可以从页面标题、说明和动作列表起步。要复刻真实产品时，自定义 `preview` 与展示层；网页、移动端和桌面端按各自布局呈现。复杂状态、角色或跨进程返回可扩展导航层，并用针对该行为的例子验证。
